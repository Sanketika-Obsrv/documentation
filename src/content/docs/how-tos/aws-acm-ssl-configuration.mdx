Kong's proxy service is fronted by an AWS load balancer. By default Kong itself terminates TLS using a Let's Encrypt certificate. With ACM, the load balancer terminates TLS using an ACM certificate and forwards plain traffic to Kong. Routing does not change — only where TLS ends.

**Requirement:** One ACM certificate for the domain (e.g. `example.com`), issued in the same AWS account and region as the cluster.

**Three files to update:**

- **Kong service load balancer annotations** — add ACM cert ARN and related settings.
- **`helmcharts/services/kong-ingress-routes/templates/ingress.yaml`** — remove the `tls:` block (NLB now handles TLS, Kong does not need it).
- **`automation-2.0/enterprise-automation/helmcharts/en-services/kong-en-ingress-routes/templates/ingress.yaml`** — remove the `tls:` block here too.

---

## Section A — New Install (Infra Not Yet Provisioned)

The Kong annotations are generated by Terraform from `terraform/aws/global-cloud-values-aws.yaml.tfpl`. Make changes through Terraform for durability.

**1. Add the Terraform variable**

In `terraform/aws/variables.tf`:

```hcl
variable "acm_certificate_arn" {
  type        = string
  description = "ACM certificate ARN for the Kong NLB"
  default     = ""
}
```

**2. Pass it into the template**

In `terraform/aws/main.tf`, inside the `aws_cloud_values` module's `template_vars` block:

```hcl
acm_certificate_arn = var.acm_certificate_arn
```

**3. Add annotations in the template**

In `terraform/aws/global-cloud-values-aws.yaml.tfpl`, inside the `kong_annotations` block:

```yaml
kong_annotations: &kong_annotations
  service.beta.kubernetes.io/aws-load-balancer-type: nlb
  service.beta.kubernetes.io/aws-load-balancer-scheme: internet-facing
  service.beta.kubernetes.io/aws-load-balancer-eip-allocations: "${elastic_ip_allocation_id}"
  service.beta.kubernetes.io/aws-load-balancer-subnets: "${load_balancer_subnet}"
  service.beta.kubernetes.io/aws-load-balancer-ssl-cert: "${acm_certificate_arn}"    # ADD
  service.beta.kubernetes.io/aws-load-balancer-ssl-ports: "443"                      # ADD
  service.beta.kubernetes.io/aws-load-balancer-backend-protocol: "tcp"               # ADD
```

**4. Set the value**

In `terraform/aws/vars/cluster_overrides.tfvars`:

```hcl
acm_certificate_arn = "arn:aws:acm:<region>:<account-id>:certificate/<cert-id>"
```

**5. Remove the `tls:` block**

Remove from `helmcharts/services/kong-ingress-routes/templates/ingress.yaml` and from the enterprise ingress template.

**6. Run the install**

```bash
cd infra-setup
./obsrv.sh install --provider aws --config ./obsrv.conf --install_dependencies false
```

**7. Deploy Helm bundles**

Continue with `core-setup` then `all` or individual bundles. Skip `letsencrypt-ssl` — it is not needed with ACM.

## Section B — Already-Running Cluster (Kong as LoadBalancer with EIP)

Infra (EIP, subnet, NLB) is already provisioned — no Terraform re-apply needed. Edit the generated values file and ingress template only.

**1. Edit `global-cloud-values-aws.yaml`**

In `helmcharts/global-cloud-values-aws.yaml`, inside `kong_annotations`, add the three ACM lines:

```yaml
kong_annotations:
  service.beta.kubernetes.io/aws-load-balancer-type: nlb
  service.beta.kubernetes.io/aws-load-balancer-scheme: internet-facing
  service.beta.kubernetes.io/aws-load-balancer-eip-allocations: "<existing, unchanged>"
  service.beta.kubernetes.io/aws-load-balancer-subnets: "<existing, unchanged>"
  # --- ADD THESE THREE LINES ---
  service.beta.kubernetes.io/aws-load-balancer-ssl-cert: "arn:aws:acm:<region>:<account-id>:certificate/<cert-id>"
  service.beta.kubernetes.io/aws-load-balancer-ssl-ports: "443"
  service.beta.kubernetes.io/aws-load-balancer-backend-protocol: "tcp"
```

**2. Remove the `tls:` block**

Remove from `helmcharts/services/kong-ingress-routes/templates/ingress.yaml` and from the enterprise ingress template.

**3. Re-deploy `coredb` bundle**

```bash
cd helmcharts/kitchen
export cloud_env=aws
bash install.sh coredb
```

**4. Re-deploy `additional` bundle**

```bash
bash install.sh additional
```

## Section C — Kong as NodePort (No EIP / Private Subnet)

This applies when org restrictions prevent using Elastic IPs or public subnets — Kong is deployed as `NodePort` and `ssl_enabled` is currently `false`.

### Option A — Keep Kong as NodePort, add an Internal ALB in front

Kong stays as `NodePort`. An internal AWS ALB is created outside Kubernetes, terminates TLS using the ACM cert, and routes traffic to Kong's NodePort.

**What the client needs to provide:**

| What | Why needed |
|---|---|
| Domain name (e.g. `obsrv.example.com`) | To request or validate the ACM certificate |
| ACM certificate ARN | Attach to the internal ALB |
| Private subnet IDs | To place the internal ALB |
| DNS access | Point the domain to the internal ALB DNS name |

**1. Update the kong-ingress-routes chart**

In `helmcharts/services/kong-ingress-routes/values.yaml`, add the `ssl_annotations_acm` block:

```yaml
global:
  ssl_annotations:
    konghq.com/preserve-host: "true"
    konghq.com/protocols: "https"
    konghq.com/https-redirect-status-code: "301"
  # ADD THIS BLOCK
  ssl_annotations_acm:
    konghq.com/preserve-host: "true"
    konghq.com/protocols: "http"    # Kong receives plain HTTP from ALB
  ingress_annotations:
    konghq.com/preserve-host: "true"
    konghq.com/protocols: "http"
```

In `helmcharts/services/kong-ingress-routes/templates/ingress.yaml`, replace the annotations block:

```yaml
  annotations:
  {{- if $.Values.global.ssl_enabled }}
    {{- if eq ($.Values.global.ssl_type | default "") "acm" }}
    {{- range $annotationKey, $annotationValue := merge $.Values.global.ssl_annotations_acm ($value.annotations | default (dict)) }}
    {{ $annotationKey }}: "{{ $annotationValue }}"
    {{- end }}
    {{- else }}
    {{- range $annotationKey, $annotationValue := merge $.Values.global.ssl_annotations ($value.annotations | default (dict)) }}
    {{ $annotationKey }}: "{{ $annotationValue }}"
    {{- end }}
    {{- end }}
  {{- else }}
    {{- range $annotationKey, $annotationValue := merge $.Values.global.ingress_annotations ($value.annotations | default (dict)) }}
    {{ $annotationKey }}: "{{ $annotationValue }}"
    {{- end }}
  {{- end }}
```

Replace the TLS block:

```yaml
  {{- if and $.Values.global.ssl_enabled (ne ($.Values.global.ssl_type | default "") "acm") }}
  tls:
  - secretName: {{ default $.Values.cert_secret_name $value.cert_secret_name }}
    hosts:
    {{- toYaml $domains | nindent 4}}
  {{- end }}
```

**2. Request an ACM certificate**

AWS Console → Certificate Manager → Request → enter the domain → DNS validation. Once status shows **Issued**, copy the certificate ARN.

**3. Get the Kong HTTP NodePort number**

```bash
kubectl get svc -n kong-ingress
# Find port mapped to 80, e.g.: 80:32080/TCP,443:32443/TCP → use 32080
```

**4. Create an internal ALB in AWS console**

EC2 → Load Balancers → Create Load Balancer → Application Load Balancer:
- **Scheme:** Internal
- **VPC:** same VPC as EKS cluster
- **Subnets:** select private subnets
- **Security group:** allow inbound port 443 from org network range
- **Listener:** HTTPS port 443 → select the ACM certificate
- **Target group:** Target type = **Instances** → Protocol **HTTP** → Port = **HTTP NodePort** (e.g. 32080) → select EKS worker nodes

**5. Update DNS**

Point the domain to the ALB DNS name via Route53 CNAME or A alias record.

**6. Update config files**

In `helmcharts/global-values.yaml`:

```yaml
global:
  domain: "obsrv.example.com"
```

In `helmcharts/global-cloud-values-aws.yaml`:

```yaml
global:
  ssl_type: "acm"
  ssl_enabled: true
  letsencrypt_enabled: false
```

:::note
**Why `ssl_type: acm` matters:** When `ssl_enabled: true` without `ssl_type: acm`, Kong routes use `konghq.com/protocols: https` — Kong expects HTTPS but the ALB sends plain HTTP, causing an infinite 301 redirect loop. Setting `ssl_type: acm` makes Kong accept plain HTTP while still generating `https://` URLs.
:::

**7. Delete Keycloak jobs and redeploy in order**

The Keycloak realm config is applied by Jobs that only run once. Delete them so they re-run with the new `https://` URLs:

```bash
kubectl delete job create-obsrv-user -n keycloak --ignore-not-found
kubectl delete job keycloak-public-key -n keycloak --ignore-not-found
kubectl delete job -n keycloak -l app.kubernetes.io/component=keycloak-config-cli --ignore-not-found
kubectl delete job keycloak-public-key -n management-api --ignore-not-found
```

Then redeploy in this order:

```bash
cd helmcharts/kitchen
export cloud_env=aws
bash install.sh oauth        # keycloak — realm config re-applies with https:// URLs
bash install.sh monitoring   # prometheus, grafana, loki
bash install.sh coreinfra    # superset
bash install.sh obsrvtools   # web-console
bash install.sh additional   # kong-ingress-routes
```

Then deploy the enterprise bundles:

```bash
cd automation-2.0/enterprise-automation/helmcharts/kitchen
export cloud_env=aws
bash enterprise.sh en-bundles
```

**8. Fix Keycloak pod FailedMount (if Keycloak pod fails to start)**

When switching from Let's Encrypt to ACM, Keycloak may fail with `FailedMount: secret 'kong-ingress-ssl-cert' not found`. Fix by disabling Keycloak TLS in `global-cloud-values-aws.yaml`:

```yaml
letsencrypt-ssl:
  enabled: false

keycloak:
  ingress:
    tls: false
    secrets: []
  tls:
    enabled: false
    existingSecret: ""
```


**9. Open ALB security group for internal pod access**

The management-console makes server-side OAuth calls via the domain URL → internal ALB → blocked by default (hairpin). Without this fix, the management-console shows `504 Gateway Timeout`.

1. EC2 → Load Balancers → find internal ALB → **Security** tab → copy the Security Group ID (e.g. `sg-0abc123`)
2. EC2 → Instances → any EKS worker node → **Security** tab → copy node Security Group ID (e.g. `sg-0xyz456`)
3. EC2 → Security Groups → open the **ALB security group** → **Inbound rules** → **Add rule**:
   - Type: `HTTPS`, Port: `443`, Source: EKS node security group ID (`sg-0xyz456`)
4. Click **Save rules**

### Option B — Change Kong from NodePort to LoadBalancer (NLB)

If the org allows it, change Kong's service type to `LoadBalancer`. Kubernetes provisions an AWS NLB directly with the ACM cert attached via annotations.

**1. Update `global-cloud-values-aws.yaml`**

```yaml
global:
  ssl_enabled: true
  letsencrypt_enabled: false
  acm_certificate_arn: "arn:aws:acm:<region>:<account-id>:certificate/<cert-id>"

kong:
  proxy:
    type: LoadBalancer
    annotations:
      service.beta.kubernetes.io/aws-load-balancer-type: nlb
      service.beta.kubernetes.io/aws-load-balancer-scheme: internet-facing
      service.beta.kubernetes.io/aws-load-balancer-subnets: "<subnet-id>"
      service.beta.kubernetes.io/aws-load-balancer-ssl-cert: "<acm_certificate_arn>"
      service.beta.kubernetes.io/aws-load-balancer-ssl-ports: "443"
      service.beta.kubernetes.io/aws-load-balancer-backend-protocol: tcp
```

**2. Remove the `tls:` block** from `helmcharts/services/kong-ingress-routes/templates/ingress.yaml`.

**3. Redeploy**

```bash
cd helmcharts/kitchen
export cloud_env=aws
bash install.sh coredb
bash install.sh keycloak
bash install.sh web-console
bash install.sh superset
bash install.sh additional
```

**4. Get NLB DNS and update DNS**

```bash
kubectl get svc -n kong-ingress
# Copy EXTERNAL-IP hostname from the LoadBalancer row
```

Create a Route53 alias record pointing the domain to the NLB DNS name.

**5. Delete Keycloak jobs and redeploy** — same as Option A step 7.

## Section E — Verification & Rollback

**Verify ACM certificate is active**

Issuer should show Amazon, not Let's Encrypt:

```bash
echo | openssl s_client -connect example.com:443 -servername example.com 2>/dev/null \
  | openssl x509 -noout -issuer
```

**Decommission Let's Encrypt (after verification)**

Uninstall the `letsencrypt-ssl` release. Delete the `kong-ingress-ssl-cert` secret from namespaces: `web-console`, `superset`, `monitoring`, `keycloak`, `dataset-api`.

**Rollback**

All paths are additive — the old Let's Encrypt path stays untouched until decommission. To roll back, revert the annotation and template changes and re-run the relevant install step.

:::caution
`ssl_enabled` must remain `true` for ACM mode. This flag controls `https://` vs `http://` URLs across Keycloak, Superset, web-console, and Kong ingress routes. Setting `ssl_enabled: false` would break all OAuth flows.
:::
