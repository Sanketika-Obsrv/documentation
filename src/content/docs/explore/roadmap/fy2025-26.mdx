## 🔧 Ongoing Priorities (Engineering in Motion)

These are active or continuous engineering efforts focused on the reliability, maintainability, modularity, and security of the Obsrv platform. They ensure smooth operations, up-to-date software components, observability, and responsiveness to support needs.

| # | Feature | 🔍 Focus Area | 🚧 Status | 📝 Notes |
|---|---------|--------------|-----------|----------|
| 1 | 🔧 Software Upgrades | Regular version upgrades for core stack components | Completed | Includes Flink, Druid, Trino, Hudi, Superset, Kafka, Kubernetes etc. |
| 2 | 🛡️ Vulnerability Fixes | Regular OSS upgrades & CVE patches | Completed | Part of monthly security hygiene |
| 3 | 👀 Dataset Observability | Track freshness, volume, schema drift | Completed | Adds alerting + insights into ingestion health |
| 4 | 🔁 Data Replay | Reprocess historical data from the backup files | Completed | API's are implemented only the UI workflows pending |
| 4 | 🐞 Bug Fixes & Support | Ongoing issue triaging, regression fixes, and L2 support | Ongoing | Handled on-demand as issues arise; includes community and internal issue handling |
| 5 | 🧠 Rule-based Auto Scaling (Pipeline & Query) | Auto-scale ingestion and query pods based on custom usage rules or schedules | Completed | Enables threshold-based scaling, cost control |
